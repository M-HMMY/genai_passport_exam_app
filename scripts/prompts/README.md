# 章を書かせるときのプロンプト

教本の各章は、ここに置いたプロンプトを Codex CLI に渡して書かせます。

> **まだ 1 つも書いていません。**この README だけが置いてあります。

## ひな形はどこにあるか

**姉妹アプリに、実際に使ったプロンプトが全部残っています。**中身を見てひな形にしてください。

- `C:\Dev\g_exam_app\scripts\prompts\` … **いちばん新しい姉妹アプリのもの。そこの README に「何をプロンプトに入れると品質が上がるか」が書いてあります**
- `C:\Dev\itpassport_exam_app\scripts\prompts\` … その 1 つ前のもの

とくに効いたのは次の 3 つでした。

- **間違えやすい事実を名指しする** … 「AI 社会原則と共通の指針は別の文書で、原則の数が違う」のように、先回りして釘を刺す
- **リンクしてよい節 ID を全部列挙する** … 列挙しないと、存在しない節へのリンクが生まれます
- **シラバスの該当箇所を読ませる** … [docs/syllabus-2026-02.md](../../docs/syllabus-2026-02.md) の、その章が担当する中項目の「学習目標」「学習項目」「詳細キーワード」

## これから置くもの

| ファイル | 用途 |
| --- | --- |
| `01-intro.md` | 入門編（`intro`）。**最初に書くこと。**用語辞典 `i-4` と略語の読み方 `i-3` が他章のリンク先になります |
| `02-a-ai.md` 〜 `12-l-business.md` | 章ごとの執筆プロンプト（11 章分） |
| `90-review.md` | 教本の通しレビュー |
| `91-review-questions.md` | 確認問題の通しレビュー |

**番号は教本の並び順です。この順に書いてください。**各プロンプトの「リンクしてよい節 ID」は、その章より前の章までしか列挙できないので、順番を飛ばすと存在しない節へのリンクが生まれます。

節割り（全 41 節の id とタイトル）は [docs/section-plan.md](../../docs/section-plan.md) にあります。**プロンプトと section-plan.md は同じ内容を持つので、節割りを変えるときは両方を直してください。**

**`90-review.md` と `91-review-questions.md` は必ず別物にすること。**教本は「書いてあることが正しいか」、問題は「**正解が本当に 1 つに定まるか**」が論点で、見る点が違います。教本用を問題に流用しないでください。

## 使い方

```bash
codex exec --cd "C:/Dev/genai_passport_exam_app" --sandbox workspace-write --color never \
  -o out.txt - < scripts/prompts/01-intro.md
```

依頼側のコンテキストを食わないよう、**`-o` で最終メッセージだけをファイルに落とす**のが要点です。

**Codex には利用上限があります。**上限に当たると、**ファイルを編集し終えた直後・報告を書く前に停止する**ことがあります。編集は残るのに報告が残らないので、`grep -c` などで期待する語を数えて、実際に反映されたかを確かめてください。

## このアプリ固有の注意

- **数式を出させないこと。** この試験に数式は出ません。`$...$` が出てきたら、たいてい説明が技術寄りに寄りすぎています
- **英略語は初出で「正式名称・訳・何をするものか」の 3 点セット。** ここが最大の得点源です
- **モデル名・サービス名には「いつ時点の話か」を必ず書かせること。** 第 2 章・第 3 章は半年で古くなります
- **第 4 章の「原則の数」に注意。** 基本理念・AI 社会原則・共通の指針は、名前が似ていて数が違います
