# 引き継ぎ書 — 次の学習アプリを作る人へ

このリポジトリ（生成AIパスポート試験）は、系譜の **5 つめ**です。6 つめを作る人に向けて、
**やり方そのもの**を残します。試験の中身は引き継げませんが、**作り方は毎回同じ**です。

`CLAUDE.md` は「このアプリをどう作るか」、この文書は「**次のアプリをどう立ち上げるか**」を書いています。

## 1. 立ち上げ — 何を持ってきて、何を捨てるか

**このリポジトリを丸ごとコピーしてから、中身を抜く**のが速いです。ゼロから作らないこと。

### 持ってくるもの（そのまま使える）

- `src/` のうち **`components/` `lib/` `pages/` `store.ts` `types.ts`** … 画面・ルータ・Markdown・図はすべて自前で、依存が React だけなので移植に引っかかりません
- **`scripts/check.ts`** … いちばん価値がある。**まず全部持ってきて、この試験に効かない検査だけ外す**（足りない分は作業しながら足す）
- `scripts/render-check.tsx` … 検査のなかで実際に React 描画する部分
- `scripts/drive.mjs` … 実ブラウザでの操作確認（後述）
- `scripts/emit_textbook.py`、`scripts/make_icons.py`、`scripts/launch.cmd`、`scripts/launch.ps1`
- `scripts/prompts/` … **中身は書き換えるが、骨組みは 16 本そろっている**
- `.github/workflows/deploy.yml`、PWA 一式（`manifest.webmanifest`、`sw.js`）

### 捨てるもの

- `src/data/textbook/*.ts`、`src/data/questions/*.ts` … 中身は全部
- `docs/syllabus-*.md`、`docs/section-plan.md` … 作り直し
- `src/data/drills.ts` の中身 … **計算問題が出る試験なら復活させる。**出ないなら骨格だけ残す

### 立ち上げで必ず変えるところ（忘れると後で痛い）

| 場所 | 何を |
| --- | --- |
| `package.json` の `name` | 新しいアプリ名 |
| `scripts/make_icons.py` の色 | **姉妹アプリと色を変える。**ホーム画面に複数並ぶので、同系色だと見分けられない |
| `.github/workflows/deploy.yml` | **対象ブランチを実際の既定ブランチに合わせる。**ITパスポート版は `main` を待つ設定なのに既定が `master` で、**一度も動いていませんでした** |
| `vite.config.ts` の `base` | リポジトリ名（GitHub Pages のサブパス） |
| `index.html` の `theme-color` | 明暗 2 本。`.topbar` の色と合わせる |

## 2. 作業の順番 — この順でないと手戻りする

1. **試験要項を公式で確認する** … 形式・問題数・時間・合格基準・実施回数。**`CLAUDE.md` の冒頭に日付つきで書く**
2. **シラバスを書き起こす** … `docs/syllabus-*.md`。中項目・学習目標・学習項目・詳細キーワードを**全部**。これが後工程すべての土台
3. **章立てと節割りを確定する** … `docs/section-plan.md`。**キーワード数で按分して章の重みを決める**
4. **入門編を手で書く** … ★重要。後述
5. **章ごとのプロンプトを書く** … `scripts/prompts/`
6. **教本を書かせる** … Codex、1 章 1 担当
7. **教本をレビューする** … **書いた人とは別の目で**
8. **確認問題を書く** … **教本を書いた人とは別の側が書く**
9. **問題をレビューする** … また別の目で
10. **体験ウィジェットを作る**
11. **実際にブラウザで動かす**
12. **公開する**

### 4 を飛ばさないこと（入門編を手で書く理由）

`src/data/textbook/intro.ts` は 3 つを兼ねています。

- **文体の見本** … 章のプロンプトに「これを読んで文体を合わせろ」と渡す
- **用語辞典と略語表のリンク先** … 全章から `[語](textbook/i-4)` で張る
- **試験の受け方の説明** … 本文の唯一の「範囲外」パート

**これを Codex に書かせると、見本が無い状態で見本を作ることになります。**先に手で書いてください。

**そのかわり、入門編は自分で書いた分だけレビューで叩かれます。**このアプリでは入門編だけで 29 件の指摘が出ました（受験端末をパソコンに限定していた、など）。**手で書いたところこそ、別の目に通してください。**

## 3. Codex に書かせる

```bash
codex exec --cd "C:/Dev/<repo>" --sandbox workspace-write --color never \
  -o out-02.txt - < scripts/prompts/02-xxx.md
```

| オプション | なぜ |
| --- | --- |
| `-o out.txt` | **最終メッセージだけ**を落とす。途中の思考ログで依頼側のコンテキストを食わない |
| `-` （標準入力） | 長い日本語をシェルの引用符で壊さない |
| `--sandbox workspace-write` | 執筆用 |
| `--sandbox read-only` | **レビュー用。指摘だけさせて、直すのは依頼側。**書き換えまで任せると何が変わったか追えません |

### 並行させるときの鉄則

- **1 ファイル 1 担当。**`src/data/textbook/<章 ID>.ts` を 1 章 1 ファイルにしてあるのはこのためです
- **同時 4 本まで。**5 本並べると利用上限に当たります
- **`npm run check` を実行させない。**並行実行でキャッシュが衝突します。検査は依頼側がまとめて 1 回
- **走っている最中に `npm run check` を叩かない。**ファイルが一瞬消えるので `Could not resolve` で落ちます

### 上限に当たったときの復旧

**上限に当たると、ファイルは書き換わっているのに `-o` の報告だけが残りません。**
何が終わって何が終わっていないか分からなくなるので、`git diff --stat` と `grep -c` で検算してください。

このアプリでも 1 巡目のレビューが **5 本とも全滅**しました。ジョブを分けるときは、
**先に 4 本流して、1 本終わってから 5 本目を流す**のが安全です。

### レビューの割り方

**章単位ではなく分量単位で割ります。**章の大きさがばらばらなので、章で割ると偏ります。

このアプリでの実績：

- **教本 41 節 → 5 ジョブ**（3〜11 節ずつ）
- **確認問題 180 問 → 4 ジョブ**（36〜57 問ずつ）

1 ジョブが大きすぎると、後半が雑になります。**40〜50 問／8〜10 節が目安**です。

## 4. レビュー工程は省けない

**書いた本人が読み返しても、間違いは 1 件も見つかりません。**系譜の実績です。

| アプリ | 対象 | 別の目 | 自己レビュー |
| --- | --- | --- | --- |
| `fe_exam_app` | 教本 約 7 万字 | 16 件（重大 4） | 0 件 |
| `itpassport_exam_app` | 教本 52 節 | **90 件超**（重大な事実誤り 30） | 0 件 |
| `itpassport_exam_app` | 確認問題 334 問 | **94 件** | 0 件 |
| `g_exam_app` | 教本 59 節 | **200 件超** | 0 件 |
| `genai_passport_exam_app` | 教本 41 節 | **105 件** | 0 件 |
| `genai_passport_exam_app` | 確認問題 180 問 | **68 件** | 0 件 |

### 目を分ける設計

**「別の目」は人格ではなく工程で作ります。**このアプリでの割り当て：

| 成果物 | 書いた側 | レビューした側 |
| --- | --- | --- |
| 入門編 | Claude | Codex |
| 教本 第 1〜11 章 | Codex | Claude → Codex（2 巡） |
| 確認問題 180 問 | Claude | Codex |

**教本と問題を同じ側に書かせないでください。**教本の誤りがそのまま問題に写ります。

### レビュー用プロンプトは 2 本作る

**教本用（`90-review.md`）を問題用に流用しないこと。**見る点が違います。

- 教本 … 「**書いてあることが正しいか**」
- 問題 … 「**正解が本当に 1 つに定まるか**」

### レビュー側の「範囲外の指摘」を見分ける

**こちらがプロンプトで例示した語が、そのまま誘導になります。**

このアプリでの実例：プロンプトに「英略語の正式名称を問う一問一答があるか確認せよ」と書いたところ、
**Codex が全節に対して「この節には略語の正式名称問題がない」と機械的に報告**してきました（8 件）。
略語を扱わない節にまで求めるのは過剰なので、採用しませんでした。

**採否はこちらで判断してください。**目安：

- **採る** … 一次資料へのリンクがある、節や章をまたいだ食い違いを指摘している、条文・数値・日付の誤り
- **疑う** … 「〜すべきです」だけで根拠が無い、プロンプトの確認項目をそのまま全件に当てはめている、
  学術的には正しいが読者（非技術職）には不要な精密化

## 5. 繰り返し出る誤りの型

**同じ型が毎回出ます。**書くときも直すときも、この一覧を手元に置いてください。

### 教本

- **一度確かめた事実が、あとから古くなっていた** … 姉妹アプリで、確認して書いた施行日が**施行の 6 日前に延期**されていた。**「確認済み」と書いた事実にも期限があります**
- **★ シラバスと一次資料が食い違う** … **このアプリで新しく出た型。**シラバスは「AI 社会原則」を 6 項目として挙げるが、
  一次資料（2019 年・内閣府「人間中心の AI 社会原則」）は **7 原則**で名前も違う。
  教本はシラバスの略記を**一次資料の内容として断定**していた。
  **試験で答えるのはシラバスの側。だが一次資料の内容として書いてはいけません。**両方を並べて、違いを明示すること
- **条文の要件の書き落とし** … 著作権法 30 条の 4 から「**又は他人に享受させる**」が抜けていた。系譜で複数回
- **「まとめて言い切る」ことで生まれる誤り** … 4 つの権利を一律に説明したが、1 つだけ例外があった
- **節をまたいだ食い違い** … 同じ用語を章によって違う説明にしていた
- **本文と図の食い違い** … 図の軸が本文と違う
- **`compare` 図の誤用** … `::` は補足であって左右の区切りではない。**要素数が偶数だと検査を素通りする。系譜で 4 回**
- **`stack` 図の向きが逆** … `stack` は**先頭が最も幅広い**
- **「よくある勘違い」が勘違いでない** … 事実の再掲になっている。`digest.ts` が直前チェックシートに拾うので影響が広い
- **説明なしの初出** … 定義より前に用語が出ている
- **本文がソースの行番号を指す** … 「最大の問題は 3 行目です」。読者の画面に 3 行目はない

### 確認問題

- **誤答の説明もれ** … 4 つのうち 1 つだけ解説で触れていない。**最も多い型**
- **★ 誤答が実は正しい（＝正解が 2 つ）** … このアプリで 2 問。片方は **Adobe Firefly が動画生成に対応したせい**で、
  書いた時点では正しかった問題が壊れていた。**情報の鮮度が、そのまま正解の数を変えます**
- **分類の軸が混ざっている** … 誤答が正解と別の軸の言葉で、両方成り立つ
- **かっこ書きの言い換えが別語だった**
- **語源の思い込み**
- **章をまたいだ重複** … 1 節ずつ見ている限り気づけない
- **正解だけが突出して長い** … 読まずに「長いものを選ぶ」で当てられる
- **★ 言い切りが誤答だけに偏る** … 誤答 3 つが「必ず」「すべて」で、正解だけ穏当。
  **言い切りを外すだけで当てられます。**このアプリで 10 問以上
- **解説が出題の手掛かりを教えている** … 「『必ず』と言い切った選択肢を疑ってください」。
  **内容ではなく試験テクニックを教えている。**本文の説明に書き換えること
- **正解の位置の偏り** … 姉妹アプリで「エ」が 288 問中 3 問。**ただし数値や順序が選択肢の問題は並べ替えない**

### 作らなくていい検査

**「解説が誤答に触れているか」を文字列一致で測るのは無理です。**
言い換えて触れているものを全部見逃しと数えます（**334 問中 233 問が誤検出**）。
やるなら一度きりの目視監査にしてください。

## 6. `check.ts` は積み上げる資産

**新しい不整合の型を見つけたら、直すついでに検査を足す。**これが 292 → 563 行の中身です。

いま入っている検査（`// ---- ` で始まる節で区切ってあります）：

ID の重複 / 参照先の存在 / 問題の形 / **問題が「解かなくても当てられる」形になっていないか** /
問題文が本番で読み切れる長さか / **図の題の「N つ」と実際の数** / 別の文字体系の混入 /
節の骨格 / ドリルの生成 / 本文の記法 / 図の中の書式 / 本文リンクの飛び先 /
数式のバックスラッシュ落ち / **実際に描いてみる**

### このアプリで足した 3 つ（次も使えます）

1. **`compare` の全要素に `::` が付いていたら疑う** … 「1 対 1 の対応表のつもり」で書くと意味が壊れる型。
   要素数が偶数だと既存の検査を素通りするので、**`::` の付き方**で見る
2. **`seq` に矢印がない行を弾く** … `A -> B :: 内容` の形でないと、`::` の右が**黙って消えます**。
   描画自体は成立するので描画検査も通ってしまう。実際に 2 か所で消えていました
3. **誤答 3 つすべてに言い切りがあり、正解にだけ無い問題**（1 問ごと）

### 閾値を全体集計にしない

**「言い切りが誤答だけに N 個」のような全体集計は、1 問ごとの偏りを拾えません。**
このアプリでも、全体では正解側にも言い切りがあったため素通りしていました。
**1 問ごとに見る検査に書き換えたら 10 問以上出ました。**

同じ理由で、**「正解だけが長い」の閾値は 1.5 倍では緩すぎます。**1.3 倍まで下げてください。
レビューで指摘されたものは 1.35 倍前後に集中していました。

### 日本語まわりで漏れやすいところ

**図の題の「N つ」検査が算用数字しか見ていませんでした。**
本文では漢数字のほうがむしろ普通なので、「**三つの要件**」と題した要素 4 個の図を素通りしていました。
検査を足したら、必ず**わざと壊して発火することを確かめてください。**

## 7. 実際に動かして確かめる

**`npm run check` は「描ける」ことしか見ていません。押したとき何が起きるかは見ていません。**

このアプリでは、**確認問題の解答が学習記録に二重登録される**不具合が、
検査・型・ビルドのすべてを通り抜けていました。原因は `Practice.tsx` で
`actions.answer` を `setSession` の更新関数の中で呼んでいたこと。
**StrictMode では更新関数が 2 回走る**ので、成績分析と復習キューが狂います。
**押してみるまで分かりませんでした。**

`scripts/drive.mjs` に、追加インストールなしでブラウザを操作する仕組みを置いてあります。

```bash
npm run dev          # 別の端末で
node scripts/drive.mjs
```

- **Node 24 の組み込み `WebSocket`** で Chrome DevTools Protocol へ直接つなぐ。Playwright を入れない
- **Edge を `--headless=new`** で起動。Windows に最初から入っている
- **使い捨てプロファイル必須。**ふだん使いの Edge が開いていると起動を奪われます
- **セレクタではなく見えている文字で押す。**画面の作りが変わっても筋書きを直さずに済む
- **`Runtime.exceptionThrown` と `console.error` を拾う。**画面は出ているのにコンソールだけ荒れている状態を見逃さない

**最低限これだけは押してください：**教本の節（ウィジェット入り）／確認問題を 1 問解いて採点まで／模試／体験ツール一覧。

なお、このスクリプトは**本文の直し漏れも見つけます。**教本と問題を直したのに
ウィジェット内の同じ文言が残っていた、という例がありました。**同じ事実を書いた場所は
`grep` で全部洗ってください。**

## 8. Windows と日本語の落とし穴

**全部、実際に踏んだものです。**

| 落とし穴 | 対処 |
| --- | --- |
| **bash のヒアドキュメントがバックスラッシュを落とす** | `cat > file <<'EOF'` を本文の編集に使わない。**Write ツールか Python** を使う |
| 本文は TS テンプレートリテラルの中 | `\n` は `\\n`、バックティックと `${` はエスケープ |
| Python の正規表現をヒアドキュメント経由で渡すと壊れる | `chr(92)`・`chr(96)` で組み立てるか、`startswith` など正規表現を使わない書き方に逃げる |
| `launch.cmd` に日本語を書くと化ける | **ASCII だけで書く。**cmd は `.cmd` を cp932 で読む。表示文字列は `launch.ps1` 側へ |
| `launch.ps1` の BOM を落とすと構文エラー | **BOM 付き UTF-8 で保存する。**PowerShell 5.1 は BOM 無しを cp932 として読む |
| ショートカットの `IconLocation` が壊れる | `WScript.Shell` で作ったあと**読み直して確認する。**パス区切りがエスケープに食われる |
| `python -c "..."` が日本語で落ちる | `python - <<'PY'` 形式にする（バックスラッシュを含まない場合のみ） |

### 大量の一括編集を安全にやる

このアプリでは、レビュー指摘の反映で**数十か所を機械的に置換**しました。事故らせないための型：

```python
def edit(path, pairs):
    s = io.open(path, encoding='utf-8').read()
    for old, new in pairs:
        assert s.count(old) == 1, (path, old[:45], s.count(old))   # ← これが肝
        s = s.replace(old, new)
    io.open(path, 'w', encoding='utf-8', newline=chr(10)).write(s)
```

- **`count(old) == 1` を必ず検証する。**意図しない箇所を巻き込む事故が消えます
- **全部の置換に成功してから書く。**途中で失敗したらファイルに触れないので、中途半端な状態が残りません
- **置換の隣にコメントで「なぜ直したか」を書く。**あとで差分を読む人（＝自分）のために

## 9. 公開

- **コミットの署名は GitHub の noreply アドレスを使う。**実メールアドレスは履歴に永久に残ります
- 個人情報・ローカルパス・API キーを含めない
- **`deploy.yml` の対象ブランチを実際の既定ブランチに合わせる**（前述）
- GitHub で空のリポジトリを作る → `git remote add origin` → `git push -u origin main` →
  Settings → Pages → Source を **GitHub Actions** に
- **Service Worker は HTTPS でしか動きません。**同じ Wi-Fi の `http://192.168.x.x:5173` では
  閲覧できてもオフライン保存は効きません。**ホーム画面に入れて使うには公開が必要です**
- `public/icons/` は**透過なしの正方形**。iOS は透明な画素を黒で塗ります

## 11. 毎回持ち越している未決事項

**次のアプリでも同じ判断を迫られます。**

- **複数選択問題への対応** … `Question` 型の `answer` は数値 1 つで、四肢択一しか表現できません。
  対応するなら `answer` を配列にし、`ChoiceList` と採点側（`Practice` / `Review` / `Mock`）を
  まとめて直す必要があります。**生成AIパスポートは「一部複数選択を含む」形式なのに未対応のまま**で、
  模試の画面に断り書きを出して逃げています
- **合否判定を出さない方針** … 合格基準が非公表の試験では、**アプリが勝手に「合格圏」と断定しない。**
  正答率・時間内に解き切れたか・分野別正答率の 3 つだけを出します。**この方針を崩す変更を入れないこと**
- **模試の構成比** … 公表されていないので、シラバスのキーワード数から按分した推定値です。
  **本番の内訳ではないと、コメントにも画面にも書くこと**
