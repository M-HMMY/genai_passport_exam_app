# 章を書かせるときのプロンプト

教本の各章は、ここに置いたプロンプトを Codex CLI に渡して書かせます。

## 置いてあるもの

| ファイル | 用途 |
| --- | --- |
| [00-common.md](00-common.md) | **全章に共通する決まりごと。**読者像・記法・節の骨格・リンクしてよい節 ID の全一覧・報告の形。**章のプロンプトは、冒頭でこれを読ませます** |
| `02-a-ai.md` 〜 `12-l-business.md` | **章ごとの執筆プロンプト。11 章分そろっています** |
| [90-review.md](90-review.md) | 教本の通しレビュー（ひな形） |
| [91-review-questions.md](91-review-questions.md) | 確認問題の通しレビュー（ひな形） |

**`01-intro.md` はありません。** 入門編（`src/data/textbook/intro.ts`）は、他章のリンク先（用語辞典 `i-4`・略語 `i-3`）と**文体の見本**を兼ねるので、依頼した側が手で書きました。**章のプロンプトはこれを見本として読ませています。**

**番号は教本の並び順です。** ただし**リンクしてよい節 ID は [00-common.md](00-common.md) に全 41 個をまとめてある**ので、書く順番は自由です。節割りは [docs/section-plan.md](../../docs/section-plan.md) で確定済みで、**プロンプトと section-plan.md は同じ内容を持ちます。節割りを変えるときは両方を直してください。**

## 使い方

```bash
codex exec --sandbox workspace-write --color never \
  -o out-02.txt - < scripts/prompts/02-a-ai.md
```

**★ リポジトリの直下で走らせてください。**`--cd` を付けていないので、別の場所から叩くと、そのディレクトリを読みにいきます。
（公開リポジトリにローカルパスを残さないため、2026 年 9 月 20 日に系譜全体から外しました。）


- `--sandbox workspace-write` … このリポジトリの中だけ書き換えを許す
- `-o out-02.txt` … **最終メッセージだけ**をファイルに落とす。途中の思考ログを読まずに済むので、依頼した側のコンテキストを食わない
- `-` … プロンプトを標準入力から読む（長い日本語をシェルの引用符で壊さないため）

複数を同時に走らせられます。**ただし 1 ファイル 1 担当**にしてください。`src/data/textbook/<章 ID>.ts` と `src/data/questions/<章 ID>.ts` が 1 章 1 ファイルで対応しているのはこのためです。

**レビューは `--sandbox read-only` で走らせます。** 指摘だけさせて、直すのは依頼した側。書き換えまで任せると、何が変わったのか追えなくなります。

## プロンプトに入れてあること（省くと品質が落ちます）

実際に姉妹アプリで効いた要素です。

1. **読むファイルの指定** … `CLAUDE.md`、`00-common.md`、**`docs/syllabus-2026-02.md` の担当中項目**（学習目標・学習項目・詳細キーワードが、そのまま書くべき内容の外枠になります）、`src/data/textbook/intro.ts`（文体の見本）
2. **書くファイルの限定** … 「他のファイルは絶対に変更しないでください」
3. **節の一覧を表で渡す** … id・タイトル・ねらい・分数・扱うキーワード。**id を決めて渡さないと勝手な id を作ります**
4. **読者像** … **「IT の基礎語彙はあるが、技術者ではない。AI は使う側」。**「サーバ」「クラウド」は通じ、「パラメータ」「潜在ベクトル」は通じない、と具体的に書く
5. **数式を禁じる** … **この試験に数式は出ません。**`$...$` を書かせないこと
6. **英略語の 3 点セット** … 初出で「正式名称・訳・何をするものか」。**このアプリ最大の得点源です**
7. **時点の明記を求める** … モデル名・サービス名の記述には「いつ時点の話か」。**第 2 章・第 3 章は半年で古くなります**
8. **章の背骨** … その章を貫く一本の考え方。用語がバラバラに見えなくなります
9. **節の骨格** … ざっくり言うと → 本論 → まとめ → quiz。`digest.ts` が拾う書式
10. **一問一答は 1 節 5 問以上** … 1 問 60 秒の試験なので、一問一答が速度対策そのもの
11. **記法の注意** … バックスラッシュのエスケープ、ヒアドキュメント禁止、**`compare` は「1 行 1 セル」で `::` は左右の区切りではない**、図の中で `**` は効かない
12. **リンクしてよい節 id の全列挙** … [00-common.md](00-common.md) にあります。省くと存在しない節へリンクして検査に落ちます
13. **間違えやすい事実の名指し** … 「GAN の生成器と識別器」「基本理念と AI 社会原則と共通の指針は別の文書で数が違う」のように先回りで釘を刺す。**姉妹アプリでは、名指しした箇所は全章で正しく書けていました**
14. **`npm run check` を実行させない** … 並行実行だとキャッシュが衝突する。検査は依頼した側がまとめて 1 回

## このアプリ固有の注意

- **数式を出させないこと。** `$...$` が出てきたら、たいてい説明が技術寄りに寄りすぎています
- **英略語は初出で 3 点セット。**
- **モデル名・サービス名には「いつ時点の話か」を必ず書かせること。**
- **第 4 章の「原則の数」に注意。** 基本理念・AI 社会原則・共通の指針は、名前が似ていて数が違います

## Codex の利用上限に注意

姉妹アプリでは、5 本を並行で走らせたとき、3 本が**編集を終えた直後・報告を書く前**に利用上限に当たりました。ファイルは書き換わっているのに `-o` の出力が空、という状態になります。

- **`-o` の出力が空でも、ファイルは変わっていることがある。** `git diff` で必ず確かめる
- **何が済んで何が残ったかは、こちらで検算する。** 指示した用語を `grep -c` で数えるのが速いです
- **同時に走らせるのは 4 本まで**にしておくのが無難です

## 報告を鵜呑みにしないこと

Codex は毎回「事実に自信がない箇所はありません」と報告してきますが、**そのまま信用してはいけません。**（そのため 90 番・91 番のレビュープロンプトでは、この報告を明示的に禁じてあります。）

- 機械的な検査は `npm run check` で必ず確認する
- 内容の正しさは、**書いた人とは別の目**で通しレビューする。省略できる工程ではありません（根拠は `CLAUDE.md`）
